# Этап 0: разведка (03.10.2026)

## Что проверено из облачного контейнера (IP в США, дата-центр Google)

| Запрос | Результат |
|---|---|
| `https://5ka.ru/` через curl | 200, но это JS-челлендж Servicepipe, а не сайт |
| `https://5ka.ru/` через Chromium (Playwright) | челлендж выполняется, ставятся куки `spjs/spsc/spid`, затем проверочный редирект → **сброс соединения** (502) |
| `https://5d.5ka.ru/api/...` (каталог, магазины, поиск) | **403**, страница блокировки X5 («сообщите в Service_connect@x5.ru») или сброс соединения |
| `https://api.5ka.ru/api/public/v1/news/` | 200: работает только старый публичный API (новости, промо), товаров там нет |

**Вывод:** из облака каталог недоступен, блокировка по IP/ASN. Живой поиск и цены
нужно проверять с российского домашнего IP, то есть у тебя на машине.
Для этого есть `smoke_test.py`.

## pyaterochka_api (Open-Inflation)

- PyPI: 0.2.2, GitHub main: 0.2.3. **В 0.2.2 есть баги:**
  - `headers={...}.update(...)` возвращает `None`, поэтому обязательные заголовки
    `x-app-version / x-device-id / x-platform` не отправляются;
  - цикл прогрева `while not ok or try_count <= 0` при неудаче никогда не завершается.

  В main оба исправлены, плюс добавлен клик по капче «я не робот». **Ставить из git, не с PyPI.**
- Транспорт: Camoufox (антидетект-Firefox) открывает 5ka.ru, проходит Servicepipe и
  перехватывает заголовки, после чего все запросы идут через `fetch` внутри страницы.
- Есть: геокод/подсказки адреса, магазин по координатам, дерево категорий, поиск,
  товары категории, карточка товара. **Корзины и авторизации нет.**

## Эндпоинты 5d.5ka.ru (сводно по обоим репозиториям)

| Назначение | Эндпоинт |
|---|---|
| Геокод адреса | `GET 5ka.ru/api/maps/geocode/?geocode=Россия, Санкт-Петербург, <улица>, <дом>` |
| Подсказки адреса | `GET 5ka.ru/api/maps/suggest/?text=...` |
| **Магазин доставки по адресу** | `GET /api/orders/v1/orders/stores/?lat=..&lon=..` → `{sap_code, shop_address, has_delivery, has_24h_delivery}` |
| Магазины на карте (физические) | `GET /api/cita/v1/stores/map?...` |
| Поиск | `GET /api/catalog/v3/stores/{sap}/search?q=..&mode=delivery&include_restrict=true&limit=..&offset=..` |
| Товары категории | `GET /api/catalog/v2/stores/{sap}/categories/{id}/products?mode=..&limit<500` (фильтры `price_min/max`, `brands`) |
| Карточка | `GET /api/catalog/v2/stores/{sap}/products/{plu}?mode=..` |

Обязательные заголовки: `x-app-version`, `x-device-id`, `x-platform: web`, плюс куки Servicepipe.

`mode=delivery` отдаёт ассортимент и цены доставки, `mode=store` отдаёт физический магазин.
По данным dreamcatchered, для доставки `orders/stores` возвращает отдельный
«магазин доставки» (тёмный склад), и он может отличаться от ближайшего магазина у дома.
Для нашей задачи нужен именно он.

## Поля товара, полезные для сопоставления (из снапшотов тестов)

```
plu, name ("Напиток Кола Добрый ... 1л"), property_clarification ("1 л", "250 г"),
uom ("шт" | "кг"), step, initial_weight_step, min_weight,
prices.regular / prices.discount / prices.cpd_promo_price, promo.rebate.units_to_activate,
is_available, stock_limit, rating.rating_average
```

Фасовку берём из `property_clarification`, а если поле пустое, то из хвоста `name`.
Весовые товары (`uom=кг`) заказываются с шагом `step`, их надо считать отдельно.
Ссылка на товар: `https://5ka.ru/product/<plu>`.

## Ограничения и риски

1. **Гео/IP-блок:** работает только с российского IP; VPN и дата-центровые IP, скорее всего, тоже блокируются.
2. **Антибот:** Servicepipe и иногда капча. Нужен настоящий браузер (Camoufox или Playwright
   в headed-режиме); куки живут недолго. Пауза между запросами ≥0,5–1,5 с
   (в dreamcatchered по умолчанию 0,45 с, после серии быстрых запросов начинаются 403/307-циклы).
3. **Корзина:** ни в одной библиотеке нет. Её эндпоинты нужно снимать из DevTools
   на залогиненной сессии (это этап 2). Поэтому для этапа 2 план с Playwright и persistent-профилем остаётся в силе.
4. Схема API неофициальная и меняется (v2/v3 поиска уже менялись), поэтому парсинг должен быть терпимым к полям.

# Дополнение: открытый API Рациона (github.com/Racion-App/racion)

Код открыт (AGPL-3.0), данные (продукты, рецепты) закрыты. Публичный API без ключа и аккаунта,
спецификация лежит в `https://racion.app/openapi.json`. Условия: личное некоммерческое использование, строить
поверх API разрешено. Лимит: 600 запросов в минуту, из них 60 на построение планов.

Проверено вживую из облака (racion.app отвечает, в отличие от 5ka.ru):

| Ручка | Что даёт |
|---|---|
| `GET /api/plans/{id}` | готовый план по ссылке `racion.app/plan/{id}`: `shopping[]` (группы → items) и `totals` |
| `POST /api/plans` | собрать неделю из параметров (`country=RU, store=pyaterochka, region=40000000000` (СПб), adults, kids[{age}], slots, exclude, excludeTags, allergens, budget, `have`) |
| `GET /api/plans/{id}/checks` | отметки «куплено» |
| `GET /api/plans/{id}/extras` | свои товары, добавленные в список руками |
| `GET /api/meta` | магазины, регионы, справочник продуктов |

Позиция списка покупок (`planner.ShopItem`):

```
ingredientId  "chicken_breast"   стабильный id продукта, ключ для кэша сопоставлений
name          "Куриное филе"
unit          g | ml | pcs
needed        240     сколько реально уйдёт в блюда
buy, packs, pack      800 / 1 / 800   округление до упаковки (фасовка по оценке Рациона, не по 5ka)
loose         true    весовой товар
pantry        true    специи, масло и т. п. («обычно есть дома»)
atHome, home          уже есть дома
cost                  оценка по Росстату × индекс сети (0,95 для Пятёрочки), а НЕ цена полки
usedIn[]              в каких блюдах
```

Что это меняет для этапа 1:
- Текст копировать не нужно: на вход идёт ссылка на план, позиции приходят структурой с точными граммами.
- Сопоставление ведётся по `ingredientId`: однажды подтверждённое соответствие «продукт Рациона → PLU в 5ka»
  кэшируется в конфиге семьи, и со второй недели почти весь список собирается без угадывания.
- Фасовку выбираем по `needed` и реальным упаковкам 5ka (на полке может найтись 2 упаковки по 400 г вместо одной на 800 г).
- В таблице две цены: оценка Рациона и реальная цена 5ka.
- Позиции `pantry`, `atHome` и уже отмеченные «куплено» по умолчанию пропускаем. `extras` (свои товары) ищем в 5ka по названию.
